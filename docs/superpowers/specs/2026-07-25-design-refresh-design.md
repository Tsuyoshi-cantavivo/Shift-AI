# ShiftAI デザイン刷新 設計書

日付: 2026-07-25
状態: 設計確定（実装計画の作成待ち）

## 1. 目的

現行UIは自ら「Modern AI SaaS — Deep Navy × Indigo / Inspired by Linear / Notion / Stripe / Vercel」と名乗るとおり、どのAI SaaSにも見える。ShiftAI 固有の視覚的アイデンティティを与える。

刷新の拠り所は製品が置かれた現場そのものに置く。想定顧客は小売・コンビニ・アパレルで、営業時間が長くシフトの重なりが複雑。主役ユーザーは店長とフランチャイズオーナー。紹介資料が掲げる価値は「店長は『組む』から『確認する』だけになります」。

したがって視覚言語は、店舗のバックヤードに実在する道具 — 壁に貼るシフト表、複写伝票、タイムカード — から借りる。装飾ではなく必然として個性を出す。

## 2. デザインの方向

**「配置表」— 現場の帳票の系譜。**

帳票の秩序（行の規律、時間軸、罫線）を土台に据え、人が触れる部分（ボタン・入力・バッジ）だけを丸める。硬すぎればただのExcelに、柔らかすぎれば密なシフト表で行を追えなくなる。その中間を狙う。

### シグネチャ要素

**24時間の配置帯。** 1行=1スタッフ、横軸=時間。営業時間（例 `04:00–翌02:00`）をそのまま軸にする。この要素がダッシュボード・シフト画面・印刷ビューを貫き、製品の署名になる。

- 1時間ごとに縦線、4時間ごとに濃い縦線
- 24:00 の位置に日付境界線（`翌日` ラベル付き）。深夜をまたぐシフトがどこで日付を越えるかは、この現場では読めないと困る
- 行はゼブラ（交互の地色）で分ける。横罫は引かない — 縦線と交差して格子になり、柔らかさが後退するため

ゼブラを使うのは**行が横に長い表**（配置帯、スタッフ一覧、希望表、監査ログ）に限る。カード・フォーム・ナビには使わない。

## 3. 決定事項

| 項目 | 決定 | 根拠 |
|---|---|---|
| 刷新範囲 | 全画面を一度に刷新 | トークンが `:root` に集約されており、色・書体の差し替えは構造上どうしても全画面に波及する |
| テーマ | ライトを正・ダークは派生 | ライトで色/コントラスト/印刷を詰め、ダークはその変換として導出する |
| Bootstrap 5 | 残すが見た目は全面上書き | 挙動（モーダル等）とユーティリティのみ利用。`app.js`（4025行）のクラス名は触らないため回帰リスクが低い |
| バーの配色 | **スタッフのロール別**（`staffs.role`） | 状態別だと全件確定後に一色になり色が情報を失う。ロールなら確定後も意味を持ち続ける |
| ロール色の割り当て | **寒色＝常勤（店長・社員）／暖色＝非常勤（パート・学生）** | 色温度そのものが雇用形態を符号化する。凡例を覚えなくても「今日は常勤が薄い」が体感で分かる |
| 状態の表現 | 色ではなく**質感**（確定=ベタ塗り／変更中=斜線／申請中=淡く破線枠） | 色＝誰が、質感＝どの段階、と軸を分けて情報の衝突を避ける |
| 時間軸 | 1時間ごとに区切る | ユーザー判断。狭い画面では細線を間引いて4時間ごとに落とす |
| ダッシュボード | 配置表を主役、数値は下に小さく | 店長が最初に知りたいのは「今日は回るのか」。集計値は確認の後 |
| ロゴ | **現状の Bootstrap Icons を据え置き** | 今回のスコープ外 |
| 紹介資料 | UI を先に刷新し、資料は後追いで合わせる | 資料は再生成が利く |

### ロール色に関する補足

学生アルバイトに**勤務時間帯の制限は設けない**。実装上の制約は次の2点のみ。

1. 月間稼働の上限が80時間（`max_hours_per_month`。指定しなければ自動で80、超過設定は拒否）
2. **学生だけで構成されるシフトの禁止**（API が `student_only` で拒否する）

2つ目は配置帯の上で直接読み取れる。ある時間帯に桜色しか並んでいなければ、それは成立しないシフトである。ロール別配色はこの判定を目視で可能にする。

将来、時間帯の制限（深夜不可など）が必要になった場合は、`staffs.role` に新しいロールを追加して表現する。既存ロールに時間帯の意味を後付けしない。

**色だけに依存しない。** スタッフ名とあわせてロール名をバッジで併記する。色覚特性のある利用者、モノクロ印刷、色が潰れるスマホ幅のいずれでもロールが読める。**ダッシュボード・シフト画面のモーダル・印刷ビューのすべてで併記する**（例外を設けない）。

配置帯の名前欄（`.tl-name`、58px／モバイル 50px／印刷 72px）では、名前とバッジを**縦に積む**。横に並べると 58px をバッジ（店長 21.6px／パート 29.4px）と分け合う形になり、名前に残るのは実測 21〜28px＝**1文字**で名簿の用をなさない。縦に積めば行の高さ（32px）に 10.2px＋7.8px の2行が収まり、**配置帯の幅を1pxも削らずに**名前 4文字とロール名の全文字を両立できる。スタッフ一覧の `.staff-cell`（名前メイン・役割サブ）と同じ構えである。

### 4.1b 意味色

`--alert` 以外の状態色。和色の系統に合わせて彩度を落とす。

**面と文字は必ずセットで扱う。** `--X` は「面の色」と「紙の上の文字色」を兼ね、
`--X-ink` は「`--X` の薄い地の上に載せる文字色」。ロール色の `--role-X` / `--role-X-ink`
と同じ構造で、`--X-ink` は `--X` に `--ink` を 30% 混ぜた確定値である。
ライトでは沈み、ダークでは浮くので、同じ配合で両テーマとも AA を満たす。

| トークン | ライト（正） | ダーク（派生） | 用途 |
|---|---|---|---|
| `--success` | `#4A7C59` | `#7FB08D` | 成功・完了。面／紙の上の文字 |
| `--success-ink` | `#3F6652` | `#A2C4AA` | `--success` の薄い地の上の文字 |
| `--warning` | `#8F6718` | `#D9B45E` | 注意。面／紙の上の文字 |
| `--warning-ink` | `#6F5724` | `#E1C78A` | `--warning` の薄い地の上の文字 |
| `--danger` | `#B14A35` | `#D97757` | 危険・エラー。面／紙の上の文字 |
| `--danger-ink` | `#874338` | `#E19C85` | `--danger` の薄い地の上の文字 |
| `--info` | `#4A6785` | `#8AA8C8` | 情報・リンク。面／紙の上の文字 |
| `--info-ink` | `#3F5770` | `#AABFD4` | `--info` の薄い地の上の文字 |

薄い地は `color-mix(in srgb, var(--X) 14%, var(--surface))` で作る。14% は
4 色 × 2 テーマの 8 組すべてが AA を満たす配合として実測で決めた（5.5 節）。

**意味色のベタ地に載せる抜き文字は `#fff` ではなく `var(--paper)` を使う。**
`--paper` はライトで明・ダークで暗と反転するため両テーマで地から離れるが、`#fff` は
ダークで地と同化する（例: `#fff` on `--warning` はダークで 1.97:1）。

### 4.3 書体

| トークン | 値 | 用途 |
|---|---|---|
| `--font-ui` | `'Zen Kaku Gothic New', system-ui, sans-serif` | UI・本文・見出し |
| `--font-num` | `'BIZ UDGothic', ui-monospace, monospace` | 数値・時刻・表内・軸の目盛り |

現行の Inter / Space Grotesk は廃止する。数値を等幅にするのは機能的要請で、表の数字は等幅でないと読み違える。

### 4.4 形と質感

| トークン | 値 | 備考 |
|---|---|---|
| `--radius-xs` | `3px` | ロールバッジなど小さなラベル |
| `--radius-sm` | `6px` | 配置帯のバー |
| `--radius` | `8px` | ボタン・入力 |
| `--radius-lg` | `10px` | カード |
| `--sh-card` | `0 1px 2px rgba(36,50,64,.04), 0 8px 24px rgba(36,50,64,.05)` | カードのみ。多用しない |

罫線は情報の区切りにだけ使う。装飾で線を足さない。影は帳票の質感を壊すため最小限にとどめる。

現行の `--radius-xl 20px` や `--sh-indigo`、グラデーション（`--grad-indigo` / `--grad-ai` / `--grad-card`）は廃止する。

### 4.5 状態の質感

| 状態（`shifts.status`） | 表現 |
|---|---|
| `confirmed` 確定 | ロール色のベタ塗り |
| `modifying` 変更中 | ロール色に白の斜線ハッチ（45度、4px/8px） |
| `requested` 申請中 | ロール色を `opacity:.55`、`1px dashed`（`--ink` 45%）の枠 |
| 〃 うち **AIドラフト** | ロール色を `opacity:.8`、`2px dashed`（`--ink` 70%）の枠 |

AIドラフトは第4の質感として扱う。DB 上は `status='requested'` なので `.tl-bar-draft` には
必ず `.tl-st-requested` が同居する。**CSS は状態ブロックより後ろに、詳細度 (0,3,0) の
`.tl-bar.tl-bar-draft.tl-st-requested` で書くこと**（同詳細度で先に書くと後勝ちで死ぬ）。

質感を分ける理由は情報の役割が違うため。申請中＝「人が出した控えめな打診」なので淡く沈める。
AIドラフト＝「機械が置いた仮の配置で、店長がこれから読んで判断する対象」なので地を読める
濃さまで戻し、枠の太さで「仮」であることを残す。**太さの差は opacity と違ってモノクロ印刷
でも残る**ため、紙の上でも申請中と区別できる。

### 5.3 導出規則

今後トークンを追加する際も、この規則に従ってダーク値を導く。

1. ロール色は**色相を保ったまま**面の明度を下げ、面上の文字を明るくする。淡いパステルをそのまま暗背景に置くと眩しく、深夜帯の閲覧に耐えない
2. 罫線・グリッド・日付境界は、**ライトでの背景とのコントラスト比を実測し、同じ比率になる値をダークで逆算する**。線の存在感が両テーマで揃い、同じ画面として認識できる
3. すべての前景・背景の組み合わせで WCAG AA（4.5:1）を満たすこと

## 8. 検証

| 項目 | 方法 |
|---|---|
| e2e 回帰 | `npx playwright test` の失敗が **6件から増えていない**こと。刷新の着手前から 6 failed / 49 passed であることを実測済み（`draft_preserves_requests` 2件・`requests_cards` 3件・`timeline_visual:114` 1件）。これらは刷新とは無関係の既存不具合で、別途対応が必要 |
| コントラスト | 設計時に全ペアを実測済み（5.4節）。実装後、実際にレンダリングされた色で再確認する |

| 狭い画面 | スマホ幅で1時間グリッドが潰れないこと。潰れる場合は細線を間引いて4時間ごとに落とす |
| キーボード操作 | フォーカスリングが視認できること |
| モーション | `prefers-reduced-motion` を尊重すること |

### e2e についての注記

`e2e/shift_detail_visual.spec.js` と `e2e/timeline_visual.spec.js` は名前に反して**ピクセル比較ではない**。`toHaveScreenshot` もスナップショットディレクトリも存在せず、時刻表示のテキストを検証している。セレクタは ID と data 属性。したがって当初懸念した「ビジュアルテストとの整合」は論点にならない。

## 9. 前提として確認済みの事実

## 10. 検討の経緯

判断の根拠として、選ばなかった案も残す。

1. **方向性** — A「配置表（現場の帳票）」／ B「時間の層（重なりを濃度で表す）」／ C「売場（棚札・黒×黄）」の3案を比較。**A の骨格に B の柔らかさ**を採ることに決定。C は毎日8時間見る業務画面にはコントラストが強すぎると判断
2. **柔らかさ** — 帳票寄り／中間／柔らか寄りの3段階で比較し、**中間**を選択。柔らかさが効くのは人が触れる部分で、格子そのものは規律が残っていた方が読みやすい
3. **時間軸の縦線** — 4時間ごと／2時間＋4時間／1時間ごとの3案。**1時間ごと**を選択（提案側の推奨は2時間だったが、ユーザー判断で1時間）
4. **バーの配色** — 「全件確定したら一色になって見づらい」という指摘を受け、状態別からロール別へ変更。割り当ては色温度で常勤／非常勤を二分する案を採用
5. **ロゴ** — 配置帯のミニチュアを提案したが、今回は据え置き

ユーザーからの評価として「今の全体の色合いは結構好き」。紙の背景と和色の系統は動かさないこと。
